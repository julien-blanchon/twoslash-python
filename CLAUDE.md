# Twoslash Python

## Project Overview

This project brings Twoslash-style hover information to Python code blocks in Shiki. It has two parts:

1. **TypeScript package** (`src/`) -- Shiki transformer that reads pre-generated JSON nodes and renders interactive code blocks with hover popups
2. **Python CLI** (`src-python/`) -- Uses multilspy to query a Python LSP, extracts hover info via AST symbol extraction, outputs JSON

## Build & Test

```bash
# TypeScript
bun install
bun run build        # tsc
bun run lint         # eslint with --fix
bun run format       # prettier

# Python (requires Python 3.12+)
cd src-python
pip install -e .
python main.py <file.py> <project_path> -o output.json
```

## Architecture

```
Python file --> [pytwoslash CLI] --> nodes.json --> [Shiki transformer] --> Rich HTML
                     |                                    |
              src-python/main.py                   src/transformer.ts
              src-python/symbol.py                 src/renderer.ts
                                                   src/twoslasher.ts
```

### TypeScript Side (`src/`)

- `index.ts` -- Public exports
- `transformer.ts` -- Shiki transformer. Hooks into `preprocess`, `tokens`, `pre`, `code`. Reads JSON from `meta.json_file_path`. Uses `splitTokens` to break at node boundaries, then wraps tokens with hover/error/completion elements
- `twoslasher.ts` -- Reads the JSON file generated by Python CLI. Returns `{ code, nodes }` as `TwoslashShikiReturn`
- `renderer.ts` -- Generates HAST elements for each node type. Mirrors `@shikijs/twoslash` renderer pattern with Python-specific defaults (lang: 'python', class: 'twoslash-python')

### Python Side (`src-python/`)

- `main.py` -- `PyTwoslash` class. Uses multilspy `LanguageServer.create()` with `"python"` config. Opens files, sends hover requests in batches, parses responses. CLI via cyclopts
- `symbol.py` -- AST-based symbol extraction. Uses both `tokenize` (comments, keywords, constants) and `ast.walk` (functions, classes, variables, decorators, imports, operators, attributes)

## Key Types

The node types follow the twoslash-protocol convention:

| Node Type | Fields | Source |
|-----------|--------|--------|
| `hover` | text, docs, tags, target | LSP hover response |
| `query` | same as hover | Explicit `^?` query |
| `completion` | completions[], completionsPrefix | LSP completions |
| `error` | text, code, level, filename | LSP diagnostics |
| `highlight` | text | `^^^` notation |
| `tag` | name, text | Custom `@tag` |

All nodes share: `type`, `start`, `length`, `line`, `character`

## Conventions

- TypeScript uses `NodeNext` module resolution with `.js` extensions in imports
- Python uses `StrEnum` for symbol types, `dataclass` for data models
- The transformer requires `json_file_path` in code block metadata to activate
- Explicit trigger (`twoslash` keyword in meta) is optional but recommended
- CSS classes follow `@shikijs/twoslash` patterns: `.twoslash-hover`, `.twoslash-popup-container`, etc.

## Dependencies

**TypeScript runtime**: `@shikijs/core`, `@shikijs/types`, `@typescript/twoslash`, `mdast-util-from-markdown`, `mdast-util-gfm`, `mdast-util-to-hast`

**Python runtime**: `cyclopts` (CLI), `multilspy` (LSP client)

## Reference Documentation

The `context/` directory contains the full source of both upstream libraries:
- `context/twoslash/` -- Original TypeScript Twoslash (node types, transformer, renderer patterns)
- `context/multilspy/` -- Python LSP client (LanguageServer API, config, types)

Key reference files:
- `context/twoslash/packages/twoslash/src/core.ts` -- Processing pipeline
- `context/twoslash/packages/twoslash-protocol/src/types/nodes.ts` -- Node definitions
- `context/multilspy/src/multilspy/language_server.py` -- LSP client API
- `context/multilspy/src/multilspy/multilspy_types.py` -- LSP types
